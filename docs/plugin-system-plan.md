# 插件系统方案（1.7.0 核心功能）

> 状态：方案定稿（Q&A 23 题全部确认，验收重点：安全）  
> 版本目标：1.7.0  
> 更新：2026-08-14

## 一、背景与目标

Quiddity 1.7.0 的核心功能为「插件系统」：

- 插件以独立小应用形态承载，权重高，相当于应用的一部分；
- 四个板块统归一个小应用：提示词（prompt）/ tool / workflow / UI（teach 板块已取消）；
- 用户任选其一进行创作，整体操作可视化高、可控度高；
- 用户可自制插件（格式因种类而异），插件自带署名（插件内设置的用户名）；
- 插件无需具体图标，取第一个文字作为图标；
- 插件通过用户导出/导入文件传播，带署名。

## 二、代码审查结论（已确认的地基）

以下能力已在现有代码中验证存在，插件系统可直接复用：

| 能力 | 现有实现 |
|---|---|
| 小应用框架 | `MiniApp` 接口、`MiniAppRegistry`、`MiniAppHost`、`MiniAppsCenterScreen`、收藏 `MiniAppStore` |
| Agent 工具链 | `AgentTool`（OpenAI ToolDefinition JSON 参数）、`AgentToolRegistry`、五大工具分类、每工具独立开关 |
| 安全门控 | `AgentSecurity`：参数校验、黑名单、确认策略、执行审计、轮次效果追踪 |
| 提示词权重架构 | `PromptBuilder.buildAgentSystemPrompt()`：区 A 人设锚点 / 区 B 能力区，注入点现成 |
| 任务编排 | `AgentWorkflowController`：工具去重、失败自动重试、执行计数 |
| 导入导出 | `DataPorter`：SAF 导出/导入、schema v1/v2 兼容、引用校验、50MB 限制、资产名白名单清洗 |
| 持久化模板 | `AgentStore` / `MiniAppStore`：AtomicFile + kotlinx.serialization + 版本迁移 |
| AI 结构化创作范式 | `QuickSetupPrompt`：用户描述 → AI 剖析归位 → 结构化解析 → 落库 |
| 文件分享 | FileProvider 已配置；`MiniAppInviteCard` 提供消息内卡片模式 |

## 三、核心设计原则（草案）

1. **插件 = 声明式数据**：插件是 JSON manifest + 对内置能力的引用与组合，不执行用户代码（安全前提，也是对创作最友好的形态）。
2. **动态注册表**：新增 `PluginRegistry`（运行期从本地 JSON 加载），与静态 `MiniAppRegistry` 并行；插件中心本身以现有 `MiniApp` 框架接入。
3. **先预览后安装**：导入走「解析 → 展示作者/版本/能力清单 → 用户确认 → 落盘」流程。
4. **受现有安全体系约束**：tool/workflow 插件只能调用用户已授权、已开启、不在黑名单的内置工具。
5. **首字图标**：插件卡片用「首个文字 + 背景色」渲染，复用 `AvatarView` / `RoundAppIcon` 模式。
6. **署名自声明**：v1 无账号体系，作者信息为自声明 + 文件内容哈希，真正防伪留待服务端能力。署名 = 插件内设置的用户名（不可设置为「九月风起待棠醒」，该 id 仅软件开发者可用）+ 全局设置头像。1.6.0 起项目闭源（开源版本止于 1.5.2）。

### 已确认决策（随问答实时更新）

- **Q1 入口（补充确认）**：插件中心仅作为小应用之一，不做默认收藏，在小应用中心里默认排第一位；**入口位置不写死**——插件本质是系统级大功能，未来可能要调整入口（如升级为主页一级入口、设置入口等），实现上抽象为「入口配置」（如 `PluginEntryMode`：小应用中心首位（v1 默认）/ 主页入口（预留）/ 设置入口（预留）），由配置项控制，改动入口不动代码结构。入口设置的具体放置位置待定，方案动工前由用户决定。
- **Q2 示例插件**：1.7.0 内置官方示例插件（每个板块至少 1 个）；示例插件与用户创作走完全相同的格式与创建流程（预置为数据文件随包发布，经同一 `PluginRegistry` 加载，不做代码特例）。
- **Q2 署名**：默认署名/官方示例署名为「九月风起待棠醒」（用户社交名，创作流程中作为默认作者名）。
- **Q3 skill 定义（已确认）**：skill = 系统提示词中一个可插拔的指令区段（任务方法论指令包）。运行期由插件系统动态拼装进 `PromptBuilder` 生成的系统提示词（人设区之后、行为区），改插件 = 改数据，不动代码；零权限、零执行；无硬性触发逻辑，靠「适用场景」字段引导 Agent 自行判断。
- **Q3 内置 skill 示例（草案，内容可后续调整）**：随包预置 5 段提示词（高效汇报 / 翻译润色 / 结构化总结 / 代码审查 / 冷静分析），署名为「九月风起待棠醒」，与用户自制走完全相同格式与加载流程。
- **Q3 更名（已确认）**：板块「skill」改名为「提示词（prompt）」，UI 展示名用「提示词」，内部类型 id 可保持 `skill` 或改为 `prompt`；提示词型插件同一时间只能启用一个，启用新插件时提示将替换当前。
- **Q1 补充（已确认）**：所有小应用（棋盘/卧底/拆弹等游戏类）不参与插件系统，其提示词不作为创作起点；「插件」是系统级入口，不视为外挂小应用。
- **插件小应用页面结构（已确认）**：主页 = 已导入/自制的插件列表，按 4 个分区（提示词 / tool / workflow / UI）展示，点击或滑动切换分区；右上角用户头像 → 个人仓库；创建插件仅在仓库页进行；保存后返回仓库页，新插件出现在对应分区；单击插件进入详情页，启用/停用在详情页决定。
- **创作页结构（已确认）**：母框按用途分类（普通聊天 / Agent / 群聊 / 后台任务 / 视觉 OCR），默认收起；母框下展开多个子框 = 各段系统自带提示词（全部开放，不含小应用）；每个子框可编辑、旁有「恢复默认」；页面底部「保存」；保存 = 另存为你的插件（内置原文不受影响，「恢复默认」仅作用于编辑框）。
- **Q4 tool（已确认）**：保持独立分区；创作 = 可视化拖拽拼接：搜索 50+ 内置工具 → 拖入拼接区 → 配置对外名称/描述/参数模板 → 保存（流程与提示词一致：回仓库页 → 工具分区 → 详情页启用）；启用后注册进 Agent 工具表（`AgentToolRegistry`）；工具总数上限 100（含系统内置约 55 个，即用户可新增约 45 个）。
- **Q4 执行与安全（待细化）**：拼接工具被模型调用时，按拖拽顺序串行执行所引用的内置工具；每次底层调用仍走现有安全门控（开关/黑名单/确认/审计）；对外参数与底层工具参数之间的映射规则待细化。
- **Q5 workflow（已确认）**：创作方式 = 简化画布（参考 `D:\Quiddity-Agent` 桌面端已落地实现）：节点（开始 / 思考 / 行动 / 验证 / 结束 + 是/否分支，可加循环）+ 连线 + 触摸交互；v1 砍掉沙箱 / 子 Agent / 评价 / 决策 / 人工 / 子流程（后置）；保留「保存软校验 + 运行前硬校验」与「默认自由执行 = 内置默认工作流」。
- **Q5 移植来源（已确认）**：`workflows.json` schema → kotlinx.serialization 原样套用（插件文件即此格式）；`validator.js` 12 条规则 → 翻译为 Kotlin 纯函数 + 单测；`workflow-engine.js` 状态机/DAG 调度 → 移植，节点内 LLM 调用与工具调用接到现有 `ChatRepository` 流式循环 + `AgentWorkflowController`；内置工作流模板（PPT 汇报 / 修 Bug / 数据分析 / 闲聊）→ 随包预置为插件数据；act 节点工具调用走现有 `AgentSecurity` 门控。
- **Q7 UI（已确认 + 细化）**：UI 插件 = 模块化美化包：主题配色 / 壁纸 / 聊天气泡（含 Markdown 内容样式）/ 图标替换 / 字体与形状（并入主题配色）；图标模块为竖排列表（左原图、右上传图，自动处理尺寸/透明/深浅色适配）；气泡借鉴 DS 网页版「Markdown 美化」思路分层落地；v1 不做完整页面布局。详见「六、UI 插件细化方案」。
- **Q8 运行边界（已确认）**：插件 = 声明式数据，不执行用户代码。理由：可执行代码可被恶意利用窃取信息（聊天记录/API Key/文件/模拟操作），Android 无安全沙箱兜底；声明式数据下插件只能调用用户已授权、已开启、不在黑名单且经确认的内置能力。四个板块（提示词/tool/workflow/UI）全部遵循此边界。
- **Q9 文件格式（已确认）**：统一 ZIP 容器，内部为 `manifest.json` + `assets/`；纯文本插件 assets 为空；文件后缀 `.quiddity-plugin`；导入时先解析 manifest，再校验包内资产引用完整性（复用 `DataPorter` 引用校验思路）。
- **Q10 AI 辅助创作（已确认）**：各板块创作页提供可选「AI 帮我生成」按钮：描述需求 → AI 生成插件内容 → 预览确认后保存；不用的人纯手填，用的人一键生成。
- **Q10 特级提示词（已确认）**：AI 辅助创作与插件保存审核所使用的系统提示词列为「特级提示词」，用户与插件均不可查看 / 修改 / 覆盖。提示词分为三类：普通可编辑提示词（母框/子框开放的约 18 段）、特级提示词（系统保护，如 AI 辅助创作 / 保存审核）、小应用提示词（不参与）。
- **Q11 首发范围（已确认）**：四个板块（提示词 / tool / workflow / UI）全部在 1.7.0 首发；分步实现、通过内测迭代解决大多数问题，不因工程量拆分版本。
- **Q13 workflow 执行与唤出（已确认，2026-08-14 更正）**：workflow 仅单轮内步骤图；在插件详情页启用后，Agent 会话内会多出一个「工作流选择设置」（常驻控件），用户在此选择 默认工作流 / 已启用的具体工作流（如 xx），选择持久化并绑定当前会话（参考桌面端输入区工作流选择器 + `conv.workflowId` 模式）；发送后由 Agent 按工具调用机制执行（注册进工具表，`dispatch` + 安全门控）。「￥ 输入框唤出」交互更正为上述常驻选择设置，不再作为主入口（是否保留为快捷方式待定）。未启用任何工作流（启用数量 = 0）时不显示该选择设置框，启用至少一个后才出现。
- **Q14 作用范围（已确认）**：按插件类型决定——提示词：创作时选择适用范围（普通聊天 / Agent / 群聊 / 全部，默认全部）；tool：仅 Agent；workflow：仅 Agent 会话内选择使用；UI：全局。manifest 增加 `scope` 字段，导入预览与详情页展示适用范围；tool/workflow 插件只在 Agent 相关界面出现。
- **Q15 权限声明与信任体系（已确认）**：tool/workflow 插件导入时展示能力清单（将使用哪些内置工具），运行仍受现有工具开关 / 黑名单 / 确认策略约束，插件不能绕过。
- **Q15 导出前自检**：创作者导出插件前必须打开自己的插件详情页，自行编辑插件信息：标题 / 内容 / 版本号；这些信息同样展示在使用者打开插件后的详情页。
- **Q15 安全警示（固定文案，详情页最上方）**：「一切行为与开发者无关，请谨慎分辨发布者的名誉状态，勿相信陌生人的文件；该文件（全部类型）涉及隐私等重要信息，请谨慎分辨！」——系统固定展示，插件不可修改。
- **Q15 开源状态**：1.6.0 起不再开源（开源版本止于 1.5.2），无需担心源码被篡改。
- **Q16 身份与防伪（已确认）**：本地 Android Keystore 生成密钥对（私钥不出设备、锁在 TEE/StrongBox），UID = 公钥 SHA-256 指纹（设备唯一、不可伪造）；导出插件时对 manifest 内容签名、公钥随包携带；导入方用公钥验签，实现防篡改 + 防冒充；真伪以 UID 为准（不解决「该 UID 是否可信」，靠固定警示文案与用户自行分辨）。插件详情页作者名下方标注 UID（如 `昵称 @ UID指纹`）；开发者「九月风起待棠醒」的插件不显示 UID，该位置显示「[官方]」。
- **Q17 聊天插件卡片（已确认）**：收到 `.quiddity-plugin` 文件时，聊天消息内渲染插件卡片（名称 / 作者 / UID / 类型 / 版本 + 「导入」按钮），点击进入导入预览；复用 `MiniAppInviteCard` 消息内卡片模式。
- **Q18 分发模式（已确认）**：以完全离线为主（传播靠导出/导入文件）；manifest 预留云端市场对接字段与入口占位（如 `marketUrl` / `downloads` 等），v1 不上线，未来有服务器可直接扩展，无副作用。
- **Q19 更新与同名冲突（已确认）**：同 ID 且版本号不同 → 直接覆盖（视为更新，保留启用状态）；同 ID 且版本号相同 → 弹窗通知，再次确认后才覆盖。版本号由作者在详情页填写，随插件展示。
- **Q20 版本兼容（已确认）**：插件 manifest 带 `schemaVersion` + 最低 App 版本号，导入时校验；格式不兼容明确提示（升级 App 或放弃导入），旧格式按迁移函数兼容（参考 `AgentStore` 版本迁移模式）。
- **Q3 提示词内容格式（补充确认）**：提示词插件的指令正文使用纯文本，不使用 Markdown 语法（换行/空行分隔即可），节省 token。
- **Q21 呈现形态（已确认）**：插件小应用主页 = 底部四个 Tab 栏（提示词 / tool / workflow / UI）点击切换，中间为插件列表，右上角入口进入用户仓库；仓库页 = 上部用户头像，中间 Tab 栏，中下部分为插件列表（创作入口所在）。
- **提示词禁含 tool（已确认）**：提示词插件只能是纯文本，禁止包含 tool 引用、外部网站连接、指定命令等内容；保存时经「特级审核提示词」自动审核，审核确认通过后插件才可保存 / 导出。
- **审核防注入（已确认）**：被审核的插件内容作为「不可信数据」处理（复用 `AgentSecurity` 不可信数据包装模式），绝不当作指令注入审核提示词，防止审核 AI 被待审内容污染 / 劫持；审核提示词本身绝对可靠、纯洁，不可被修改。
- **tool 参数只读（已确认）**：tool 插件仅可拼接内置工具（连接顺序），工具本身的参数只读不可修改（参考桌面端画布「参数固定只读」）；插件对外名称 / 描述由用户在插件详情页标题栏目填写（与提示词 / UI 插件同一套详情页编辑）。
- **审核不通过处理（已确认）**：审核不通过 → 提示原因 → 用户修改 → 重新审核；不通过不允许保存 / 导出，不可松懈（涉及用户信息安全）。
- **审核模型要求（已确认）**：审核使用用户配置的默认 API，且必须为完整级（FULL）；默认 API 非完整级时，向下查找其他可用完整级模型；无完整级可用 → 提示用户先配置，不允许保存。创建插件前先检查用户 API 配置情况。
- **Q22 高危能力处理（已确认）**：分层机制——内容审核（特级提示词）管用户自由输入的类型（提示词 / UI，禁外部链接 / 指定命令 / 恶意内容）；能力权限管 tool / workflow 的高危工具引用：导入预览显著列出能力清单（尤其高危项），高危项默认禁用、用户手动开启，每次调用仍受现有开关 / 黑名单 / 确认约束。
- **Q23 验收标准（已确认）**：完整验收——构建通过 + 单测覆盖（manifest 解析 / 版本迁移 / 审核逻辑 / 签名验签 / 工作流校验器 / 注入与安全门控）+ 模拟器全流程手工验证（创建 → 审核 → 保存 → 仓库 → 启用 → 导出 → 再导入 → 更新覆盖），四个板块各跑一遍；**安全为重点**。

## 四、四大板块插件形态草案

| 板块 | 插件内容 | 运行机制 | 相对难度 |
|---|---|---|---|
| 提示词（prompt） | 提示词指令包（注入系统提示词区 B/C） | 启用后拼入系统提示词；同一时间仅启用一个 | 低 |
| tool | 内置工具的可视化拖拽拼接（搜索 + 拖动 + 配置名称/描述/参数） | 启用后注册进 `AgentToolRegistry`，可被模型调用；工具总数上限 100（含内置） | 中 |
| workflow | 简化画布（节点 + 连线 + 是/否分支） | 移植 Quiddity-Agent workflow 引擎（DAG 调度 + 状态机 + 校验器）；节点内调用走现有安全门控 | 中 |
| UI | 主题令牌包（颜色/壁纸/形状/字体） | 导入后应用到主题系统 | 高（完整布局更甚） |

### 内置提示词示例清单（草案）

| 技能名 | 适用场景 | 指令正文要点 |
|---|---|---|
| 高效汇报 | 汇报/说明类任务 | 先结论后细节；结构：结论 → 依据 → 下一步；不确定处明确标注；善用列表与数字 |
| 翻译润色 | 翻译/改写类任务 | 忠于原意；术语全篇一致；适配目标语言习惯与指定风格；不确定译法明确标注 |

| 代码审查 | 代码评审类任务 | 按严重程度排序；先功能正确性，再安全/性能/可读性；给出具体修复建议 |

## 五、各板块创作方式草案（先行确认）

## 六、UI 插件细化方案（深查代码后）

> 已深查：`Theme.kt` / `Color.kt` / `Shape.kt` / `Motion.kt` / `MessageBubble.kt` / `MarkdownParser.kt` / `CodeBlockView.kt` / `WallpaperPanel.kt` / `ListWallpaperPanel.kt` / `SettingsStore.kt` / `AvatarView.kt`

### 6.1 定位与范围

- UI 插件 = 模块化美化包：一个插件可含一个或多个模块。
- v1 支持：主题配色 / 壁纸 / 聊天气泡（含 Markdown 内容样式）/ 图标替换 / 字体与形状（并入主题配色）。
- 不做完整页面布局（声明式组件树 + 运行时渲染器，成本过高，后置）。
- 启用规则：主题类模块（配色/字体形状/壁纸）同类同时仅启用一个；气泡与图标可与其他类型共存；同一图标仅一个来源。

### 6.2 模块 → 现有代码对应与覆盖点

| 模块 | 可编辑项 | 现有代码 | 覆盖方式 |
|---|---|---|---|
| 主题配色 | 深/浅两套 21 色令牌 | `Theme.kt` 的 `QuiddityLightColors` / `QuiddityDarkColors`（primary/onPrimary/primaryContainer/background/surface/surfaceVariant/surfaceContainer*/outline*/error 等） | 插件 tokens 覆盖默认色板；`QuiddityTheme` 改为「默认 + 插件覆盖」两段合并，仍保留 0.4s 平滑过渡 |
| 聊天气泡 | 用户/AI 气泡底色、边框、圆角、文字色 + Markdown 渲染样式（标题/链接/引用/代码/加粗/列表） | `MessageBubble.kt`（bubbleColor / bubbleBorderColor / `BubbleShape` / `applyMarkdownStyles`）、`MarkdownParser.kt`、`CodeBlockView.kt` | 气泡与 Markdown 样式令牌参数化，由启用的插件提供 |
| 壁纸 | 聊天默认壁纸 + 列表壁纸 + 暗化程度 | `WallpaperPanel` / `ListWallpaperPanel`（选择 → 复制内部存储 → 裁剪 → 对比度遮罩）、`WallpaperContrast` | 插件资产落地到 `filesDir/ui_plugin_assets/<id>/`，沿用现有裁剪与对比度管线 |
| 图标 | 系统图标逐个替换（发送/返回/菜单/箭头等） | Material Icons 用法（`Icons.Rounded.*`） | 竖排列表：左原图、右上传图；图标渲染层支持 Bitmap 覆盖 ImageVector |
| 字体与形状 | 全局字体族/字号/圆角 | `Typography`、`Shape.kt`（QuiddityShapes + UserBubbleShape/AiBubbleShape/InputBarShape） | v1 并入主题配色模块 |

### 6.3 插件数据格式（manifest schema v1 草案）

```json
{
  "id": "ui_xxx",
  "name": "示例主题",
  "author": "九月风起待棠醒",
  "version": "1.0.0",
  "type": "ui",
  "modules": ["theme", "bubble", "wallpaper", "icon"],
  "theme": {
    "light": { "primary": "#...", "onPrimary": "#...", "background": "#...", "surface": "#...", "outline": "#..." },
    "dark": { "primary": "#...", "onPrimary": "#...", "background": "#...", "surface": "#...", "outline": "#..." }
  },
  "bubble": {
    "userBubble": { "shape": { "tl": 16, "tr": 16, "br": 4, "bl": 16 }, "background": "#...", "textColor": "#...", "borderColor": "#...", "borderWidth": 1 },
    "aiBubble": { "shape": { "tl": 16, "tr": 16, "br": 16, "bl": 4 }, "background": "#...", "textColor": "#...", "borderColor": "#...", "borderWidth": 1 },
    "markdown": { "headingColor": "#...", "linkColor": "#...", "codeBg": "#...", "codeText": "#...", "quoteColor": "#...", "bulletColor": "#..." }
  },
  "wallpaper": { "chat": "assets/chat.png", "list": "assets/list.png", "chatDarken": 0.3, "listDarken": 0.3 },
  "icons": [ { "id": "send", "asset": "assets/icons/send.png" }, { "id": "back", "asset": "assets/icons/back.png" } ]

```

> 字体与形状 v1 并入 theme（如 `fontScale` / `shapeRadius`），不单独成模块。实现时用 kotlinx.serialization 定义，未知字段忽略，带 `schemaVersion`。

### 6.4 资产处理（图标 / 壁纸，高度可控的关键）

- **图标**：上传后统一规格处理——按语义尺寸等比缩放（如 96dp）、透明 PNG 化、深浅色描边自动适配；竖排列表左侧展示原图标、右侧展示用户上传图，逐项生效预览。
- **壁纸**：选择图片后按屏幕宽高比裁剪（复用现有 `ImageCropper`），沿用自动亮度采样 + 对比度遮罩管线。
- **安全与落地**：资产复制到内部存储插件目录（仿 `ListWallpaperPanel` 的 `list_wallpapers` 模式）；资产名白名单清洗（复用 `DataPorter.safeAssetName`）；格式白名单 PNG/JPEG/WebP；单资产大小限制。
- **恢复默认**：每个模块、每个图标都有独立「恢复默认」；页面底部统一「保存」。
- **实时预览**：内嵌样例聊天界面（复用 `MessageBubble` 组件）预览配色 / 气泡 / Markdown 样式；图标列表即时生效。

### 6.5 生效优先级（v1）

- 插件启用时接管对应模块；停用或恢复默认即还原内置样式。
- 会话级手动壁纸优先于插件默认壁纸（会话覆盖 > 插件 > 内置）。
- 深/浅色两套分别生效，跟随 `darkMode`。
- 与现有设置（`darkMode`、`markdownEnabled`、`bracketGrayEnabled`、壁纸）不冲突：插件只覆盖其声明的模块。

### 6.6 v1 验收

- 导入 → 启用 → 全局实时生效；逐模块 / 逐图标恢复默认；停用完整还原。
- 深/浅色两套预览正确；图标尺寸 / 透明 / 描边适配正确；壁纸裁剪与对比度正确。
- 与现有设置项（darkMode / markdownEnabled / 壁纸 / 字体）无冲突。
