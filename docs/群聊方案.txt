群聊功能方案（1.5.0）

文档说明：本文档为纯文本格式，不使用 markdown。随讨论逐轮更新，每确认一轮写入一轮，确保不遗漏。

一、总目标
1. 群聊功能定为 1.5.0 更新内容，至少要做出尝试。
2. 所有项目文档统一使用纯文本格式，避免 markdown 等浪费 token 的格式。
3. 方案要做到全面、成熟、可靠。

二、群聊规模
1. 群聊共 4 个“人”：1 个用户 + 最多 3 个 LLM 成员。
2. 成员数量上限固定为 3。
3. 1.5.0 支持创建多个群聊，群聊列表页展示所有群聊。
4. 新私聊默认名“新会话 1、2、3…”，新群聊默认名“新群聊 1、2、3…”，按创建顺序递增，删除不补号，两类各自独立编号。
5. 默认名可被后续设置覆盖：用户可随时改名；设置 AI 名字后的自动改名逻辑继续生效。
6. 建群流程：在首页“群聊”模式下点击新建按钮创建群聊；从私聊列表勾选 1～3 个成员（逐个校验用户名、AI 名、API 测试通过），群名可空（自动编号“新群聊 N”），创建后进入群聊。私聊模式下点击新建按钮直接创建私聊。私聊/群聊各自在对应模式下新建，不做二选一弹窗。

三、发送与回复模式
1. 群聊发送模式定为“头像点击发送”。
2. 流程：用户编辑消息 → 发送 → 点击成员头像 → 该成员回答（接话）。
3. 用户不点击头像就不会有回复。
4. 暂时只有这一种回复模式：由用户决定谁来作为下一个发言人。
5. 点头像没有前置限制，不要求用户先发送消息，可随时点击。
6. 输入框里未发送的文字不参与回复，成员只基于已发送的群聊记录回复，等同“让 AI 先说”。
7. 群聊初始为空，不插入任何提示气泡。
8. 首次使用群聊功能时默认弹出教程弹窗；群聊页面右下角有问号按钮，点击可再次打开教程。
   教程内容（列点、通俗）：
   • 发送消息后，点一下成员的头像，TA 才会回复你
   • 可以连着点好几个头像，TA 们会排队依次回复（最多 1 个在回复、2 个在排队）
   • 不点头像就没人回；想听谁说，就点谁
   • 成员管理、上下文条数等都可以在群聊设置里调整

四、排队机制
1. 点击 a 头像后：a 头像变灰，并在头像中央显示三点加载动画，表示正在回复。
2. 在 a 回复期间点击 b：b 头像变灰，头像中央显示数字 1，表示第一个排队。
3. 再点击 c：c 头像变灰，头像中央显示数字 2，表示第二个排队。
4. a 回复完毕：a 头像恢复原样；b 开始回复，b 头像中央的数字 1 变为加载动画；c 头像中央的数字 2 变为 1。
5. 限制：正在回复的最多 1 个，排队最多 2 个。
6. 正在回复的成员可以中途停止：回复期间发送键变为停止键。
7. 停止行为有两种模式，可在会话内设置切换：
   模式 A：只停止当前正在回复的成员，排队的照常顺位递补。
   模式 B（默认）：停止时同时清空整个队列，头像全部恢复。
8. 队列进行中用户仍可发送新消息：新消息进入群聊记录，不影响正在进行的回复；成员回复的上下文在点击头像那一刻定格，之后产生的新消息不会被加入正在进行的回复，当前队列回完后用户可再点名回复新消息。

五、上下文格式
1. 消息前面要写名字（用户名、AI 名），格式为“名字：内容”。
2. 不需要让 AI 知道谁是用户，用户与 AI 平等对待，不做角色区分。
3. 示例（名字为占位示例，不带角色标注）：
   1：你好
   a：你好呀
   b：你们好~

六、上下文范围与记忆
1. 不带私聊记忆，成员回复只基于群聊对话记录。
2. 群聊记录只取最近 N 条，默认 50 条，可在群聊设置里调整，范围 1～200。
3. 记忆模式与私聊一致，按模型分级：
   基础级：只带最近 N 条群聊记录。
   进阶级/完整级：可自行用工具检索完整群聊消息。
4. 模型分级定义：应用把每个模型按能力分为三级——基础级（入门轻量模型）、进阶级（能力中等）、完整级（实测得分高或厂商主流模型；自定义服务商强制归完整级）。
5. 目前不做额外记忆功能，用户有需求再说。
6. 群聊消息只存在群聊会话里，不写回成员私聊，成员私聊历史不受群聊影响。

七、成员来源与校验
1. 成员从私聊引用（邀请），直接拿私聊的角色卡。
2. 角色卡继承内容：AI 名字、头像、人设；不继承场景。
3. 用户设置不随邀请复制进群聊；回复时按第九条取该成员私聊里的用户人设。
4. 加入角色时必须确保设置齐全：用户名、AI 名、API 测试通过，否则不允许加入。

八、模型配置
1. 成员被点名回复时，使用各自私聊的模型配置：模型、API key、最大 token 均按各自私聊独立。

九、用户设置（最终版，推翻早期“群聊统一填写用户设置”的说法）
1. 群聊不设共享用户人设。
2. 每个模型拿到的用户信息不一样：成员 A 回复时，注入的用户人设 = A 私聊里的用户人设。
3. 转述里用户消息的名字 = 该成员私聊用户人设里的名字，不统一。
4. 用户名必须设置，不能为空；此规则同步到私聊，私聊也必须设定用户名才能聊天。
5. 早期“用户名在群聊设置里填、可从会话复制”的决定作废。
6. 强制范围：新建和已有会话都生效；会话内用户名未设置时，进入会话先弹窗要求填写，未填写不能发送消息。

十、群聊设置
1. 群聊设置包含：群名称、上下文条数 N、成员管理（查看/添加/移除）。
2. 不包含共享用户人设项。
3. 群聊暂不支持主动消息/时间库，群聊设置里不显示时间库入口。
4. 成员管理规则：
   成员可随时添加/移除，最多 3 个，最少 1 个。
   成员被移除（踢出）后：头像栏和成员列表不再显示该成员；他发过的历史消息气泡保留，气泡旁的头像保留（快照），不变成占位图。
   被移除成员之后可重新邀请回群。
5. 添加成员交互：弹出私聊列表勾选，显示会话名、AI 名字、头像与校验状态；最多选到 3 个；未通过校验的置灰并提示原因。
6. 私聊删除保护：当私聊被群聊引用时，删除前弹确认提示；确认后该成员从群聊中被“踢出”：头像栏/成员列表移除，但他在群聊中的消息气泡与气泡旁头像（快照）保留，群聊聊天记录保留。
7. 群聊因踢出导致成员数为 0 时：群聊保留、历史可查看，但不能点名回复，顶部提示“请添加成员”，点击可跳转成员管理。
8. 群聊设置入口在群聊页面内；会话级设置：群名称、上下文条数 N、成员管理、停止模式 A/B。
9. 全局设置沿用现有总设置：延迟输出（开关、每字毫秒数）、首次使用群聊教程弹窗（记录已看过，只弹一次）。无新增全局群聊设置项。

十一、头像栏 UI
1. 头像点击 UI 设在输入框上方，方便点击。
2. 头像栏随输入框跳起/收下一起动（跟随键盘）。
3. 头像栏只显示 3 个 AI 成员头像，按加入顺序排列；不显示用户自己的头像。
4. 头像栏向右靠齐。
5. 对话气泡与头像栏不重叠：消息列表区域不伸入头像栏，气泡不会与头像栏相互遮挡。

十二、消息展示
1. 每条消息左侧显示发送者头像，气泡上方或气泡内显示名字。
2. 成员消息用角色卡头像 + AI 名字；用户消息显示“我”。
3. 用户消息带全局用户头像；未设置时使用默认占位头像（通用人像）。
4. 正在流式输出的消息气泡带打字动画。
5. 点击气泡后展开操作选项：撤回、重新生成、改写，复用私聊已有能力。
6. 用户可撤回/改写自己的消息；成员消息可重新生成/改写；操作只作用于该条消息，不打断当前队列。
7. 群聊消息纳入全局搜索；群聊会话内提供聊天记录搜索，与私聊一致。全局搜索与会话内搜索是两个相互独立的模式。
8. 群聊消息支持长图导出：多选生成长图分享，气泡带发送者名字，复用私聊现有实现。
9. 群聊不提供单独的“清空聊天记录”入口（与私聊一致，现有私聊已下线该入口）；删除群聊走首页多选。

十三、错误处理
1. 成员回复失败时重试 5 次。
2. 每一次重试都弹出通知，例如“网络错误，重试中 1/5”。
3. 任一成员重试 5 次仍失败后，整个队列取消，所有头像恢复。

十四、首页与会话列表
1. 会话列表右滑可以丝滑滑到群聊列表。
2. 屏幕下方有“私聊”“群聊”两个按钮，点击可滑动切换。
3. 用户在哪个页面，哪个词就高亮：浅色模式高亮为黑色，深色模式高亮为白色。
4. 高亮色（指示块）随滑动进度在两个词之间移动，与滑动联动。
5. 群聊卡片显示：群名称 + 更新时间 + 成员头像拼合图（3 个成员头像拼在一起），不显示消息预览。
6. 群聊支持删除：复用现有会话删除交互（多选/长按），删除时群聊记录一并删除，成员私聊不受影响。

十五、文档维护规则
1. 每问一轮就写一轮：每次确认的新决策立即写入本文档，确保不遗漏。
2. 本文档保持纯文本格式，不用 markdown。

十六、现有代码基础（供实施参考）
1. 数据模型已预留：Conversation.type=GROUP、memberConversationIds、groupMemory、Message.senderId。
2. ChatRepository 已预留三个接口：streamGroupMemberReply、decideGroupResponder、compressGroupMemory，目前抛 NotImplementedError。
3. PromptBuilder 已有群聊提示词构建器：成员 system prompt、转述、接话判断、记忆压缩。
4. 现有 buildGroupTranscript 输出格式为“[名字] 内容”，与第五条“名字：内容”需在实施时统一。
5. MessageStreamCoordinator 已支持 senderId 从创建起透传。
6. 首页已有私聊/群聊分节查询接口（conversationsGroupedByType），群聊列表分区可用。

十七、数据导出导入
1. v2 导出包含群聊：群聊会话、群聊消息、成员引用。
2. 导入时恢复群聊，改掉现有“群聊整体跳过”的逻辑。
3. 导入时做引用校验：成员会话 id、消息 senderId 悬空时按现有规则处理，群聊条目计入跳过清单。

十八、延迟输出定义（私聊与群聊共用）
1. 延迟输出 = 按回复字数决定加载动画持续时长，不再按“流式输出本身”算。
2. 回复内容仍然流式输出，每个字按“每字毫秒数”淡入出现，输出速度保持不变。
3. 加载动画（私聊的气泡状态、群聊成员头像的三点）在整个逐字淡入期间持续，全部文字显示完才停止。
4. 网络快时动画不会提前结束；总时长约等于“回复字数 × 每字毫秒数”。
5. 群聊成员头像的加载动画同样适用此规则。

十九、设置原则
1. 全局设置对整个应用有效，私聊/群聊统一生效。
2. 会话内（私聊/群聊）不重复设置全局项。
3. AI 回复切分（按句末标点切分多条消息）为全局设置，群聊统一生效。
4. 会话内只保留真正会话级的设置：群聊为群名称、上下文条数 N、成员管理、停止模式；私聊为既有会话级设置。
