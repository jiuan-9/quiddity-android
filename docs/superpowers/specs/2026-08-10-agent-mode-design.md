# Agent 模式设计草案（v0.1）

> 日期：2026-08-10
> 状态：讨论中（方案未定稿，待决策问题见文末）
> 目标：在 Quiddity Android 中加入第三个模式「Agent」，让 LLM 能读取手机信息、执行系统级操作，能力分为基础 / 进阶 / Root 三档，并给出实现路径与难度评估。

## 1. 背景

当前 App 已有两个模式（首页双 Tab：私聊 / 群聊）和一个小应用中心（棋盘 / 谁是卧底 / 拆弹等娱乐向）。
用户希望新增「Agent」模式：AI 不仅聊天，还能替用户在手机上做事。

## 2. 现状基础（可复用资产）

### 2.1 LLM 工具调用环（已存在，无需从零搭建）

- `ToolDefinition`（OpenAI 兼容 function 格式）+ `ResponsesTool`：定义工具声明；
- `ChatStreamParser`：流式聚合 `tool_calls` 增量分片；
- `ChatRepository.runWithToolRound`：完整双轮循环（第一轮出工具调用 → 回填结果 → 第二轮出最终答复）；
- 现有工具：`read_memory`（记忆抽屉检索）、`search_chat`（聊天记录检索）。
- 缺口：工具执行是硬编码的，需要泛化成「工具注册表 + 分发器」。

### 2.2 后台能力（可复用）

- 前台服务（dataSync）、AlarmManager、开机广播、精确闹钟 / 电池优化授权引导；
- 分发方式为官网下载 + 自更新（非 Play 优先），无障碍 / 设备管理等能力无 Play 政策风险。

### 2.3 首页扩展点

- `HomeScreen` 的 `HorizontalPager(pageCount = 2)` 与 `ChatTypeTabBar` 硬编码双 Tab，扩三 Tab 改动面小；
- 小应用框架（`MiniApp` + `MiniAppRegistry`）也可承载 Agent，但定位不同。

## 3. 能力分级

分级原则：**感知 / 收集类 = 基础；修改 / 创建 / 删除类 = 进阶；root = 完整（可选增强）**。

### 3.1 基础（感知 / 收集，仅系统授权，无需电脑）

| 能力 | 实现途径 | 授权方式 |
|---|---|---|
| 读取当前前台应用 | UsageStatsManager / AccessibilityService 窗口事件 | 系统设置授权 |
| 读取屏幕内容 / 界面节点 | AccessibilityService | 系统设置手动开启（一次性） |
| 读取通知 | NotificationListenerService | 系统设置手动开启（一次性） |
| 读取剪贴板 | 无障碍读取（Android 10+ 后台直接读被限制） | 随无障碍授权 |
| 应用使用记录（何时用了多久） | UsageStatsManager + `PACKAGE_USAGE_STATS` | 系统设置授权 |
| 已安装应用列表 | PackageManager + `QUERY_ALL_PACKAGES` | 侧载分发无限制 |
| 截屏（当前画面给模型看） | MediaProjection | 每次会话系统弹窗授权 |
| 系统基础信息（电量 / 网络 / 存储 / 型号） | 公开 API | 无需授权 |
| 通讯录 / 短信 / 定位 / 相机 / 麦克风（可选） | 标准危险权限 | 系统弹窗一次授权 |

### 3.2 进阶（修改 / 创建 / 删除，经 Shizuku，需 PC 一键授权）

| 能力 | 实现途径 |
|---|---|
| 停用 / 启用应用 | `pm disable-user` / `pm enable` |
| 修改应用权限（AppOps） | `cmd appops set` |
| 卸载第三方应用 | `pm uninstall`（shell 通道） |
| 强制停止应用 | `am force-stop` |
| 安装 APK | `pm install`（shell 通道） |
| 修改系统设置项 | `settings put secure / global` |
| 启动 / 拉起其他应用或深链 | `am start`（普通 API 亦可，shell 更全） |
| 模拟点击 / 滑动 / 输入 | 无障碍 `performAction` / `dispatchGesture`（技术上只需基础授权，但属操作类，按进阶对待 + 确认） |

要点：`pm disable` 停用其他应用需要签名级权限 `CHANGE_COMPONENT_ENABLED_STATE`，普通第三方应用拿不到，进阶能力必须经 Shizuku 通道（已定稿）。

### 3.3 完整（root，可选增强，不做必需）

| 能力 | 说明 |
|---|---|
| 停用 / 卸载系统应用（含预装） | 普通用户无此需求，仅进阶玩家 |
| 读写系统分区与任意应用私有数据 | 可访问 `/data/data` 等 |
| 系统级改造（Magisk / Xposed、hosts、开机自启） | 超出发包能力范围 |

已定决策：**root 不列为产品必需**（普通用户门槛过高），作为已 root 设备的可选增强；主流路径为 Shizuku。

## 4. 方案概览

## 4. 方案概览

### 4.1 入口

Tab 顺序（定稿）：**Agent(0) / 私聊(1) / 群聊(2)**，打开应用默认停在私聊。
- Agent 在私聊**左侧**：从私聊向右滑 → Agent；群聊在私聊右侧：向左滑 → 群聊；
- 右滑手势与点 Tab 等效。

**Agent 页 UI（定稿）**：
- 主界面 = Agent 会话列表，**与私聊 / 群聊完全同款列表组件**，不新增任何面板 / 状态卡；
- Agent 会话消息采用**纯文本直排（无气泡）**排版（Claude / ChatGPT 风格），推翻现有气泡 UI；仅 Agent 模式生效，私聊 / 群聊气泡不变；
- 全局总设置仍生效（字体大小、主题等）；
- 左上角为 Agent 专属设置按钮（不复用聊天页汉堡菜单），内容见 4.9；
- 会话内保留汉堡菜单（人设卡等），默认人设未设置时使用冷峻默认提示词，见 4.8。

### 4.2 架构

```
Agent Tab（会话 UI，复用 ChatScreen 形态）
   └─ AgentViewModel（Agent 专用，独立于私聊 ChatViewModel）
          └─ 工具注册表 AgentToolRegistry（name -> 定义 + 执行器）
                 ├─ 只读工具：list_apps / read_screen / read_notifications / usage_stats
                 ├─ 进阶工具：disable_app / appops_set（经 Shizuku 或 su）
                 └─ 权限分级门控 + 用户确认 + 审计日志
   └─ 通道层
          ├─ AccessibilityService（读屏）
          ├─ NotificationListenerService（通知）
          ├─ ShizukuClient（进阶，免 root）
          └─ SuClient（root 通道）
```

### 4.3 分期实施

- **P0（约 1-2 周）**：第三 Tab（Agent 控制台：状态卡 + Agent 会话列表）+ Agent 会话（复用 Conversation 新增 `AGENT` 类型）+ 工具注册表泛化 + 只读工具（应用列表 / 通知 / 用量 / 读屏文本）。跑通「看得到手机」。
- **P1（约 1-2 周）**：Shizuku 接入 + `disable_app` / appops 工具 + 操作确认与白名单 + 审计日志 + **PC 一键授权工具（Python + PyInstaller，仅 USB）**。跑通「停用应用」。
- **P2（约 1-2 周）**：提示注入防护（不可信内容包裹 / 参数校验 / 命令模板化）+ 单测 + 真机验证。
- **V2（未排期）**：root `su` 通道（可选增强）、无障碍模拟点击 / 滑动（默认关闭 + 白名单 + 确认）、常驻 Agent 循环（监听通知自动执行，需 Android 14 `specialUse` 前台服务）。

### 4.4 PC 一键授权工具（自研，配套交付）

目标：把「装 Shizuku + adb 授权 + 启动服务」降到「插线 → 双击 → 完成」。
**仅面向 Android 8-10 设备**（Android 11+ 可用无线调试在手机本地配对，免电脑，见 4.5）。

形态与流程：
1. 用户手机安装 Quiddity 与 Shizuku APK（官网下载）；
2. 工具内图文引导开启 USB 调试（含驱动提示）；
3. 插线后工具自动 `adb devices` 检测设备；
4. 自动检测 Shizuku 是否安装（未装则 `adb install` 自动安装）、adb 授权是否完成（手机端弹窗确认）；
5. 一键执行 `adb shell sh .../start.sh` 启动 Shizuku 服务；
6. 完成提示，打开 App 即用。

技术选型建议：复用团队已有 Electron 经验（Quiddity-Agent 桌面端），或 Python + PyInstaller / Go 单文件；内置 `platform-tools` 的 adb（或首次启动自动下载）。

已知限制：非 root 手机每次重启后 Shizuku 服务失效，需要重新插线一键授权；App 内检测到 Shizuku 未运行时应主动提示用户（仅 root 手机可免）。

### 4.5 版本兼容与状态检测（难点专项）

**版本结论**：本 App minSdk 26（Android 8.0），Shizuku v13+ 支持 Android 7.0+，两者无冲突——凡是能装 Quiddity 的手机都能装 Shizuku。分档：

- Android 11+：无线调试在手机本地配对（Shizuku 内输 6 位配对码），**无需电脑**；重启后需重新启动（配对码可能重输）。
- Android 8-10：必须电脑 + USB（一键工具目标人群）；每次重启重授权。
- Android <8：不在支持范围（minSdk 26 已排除）。

**检测难点不在版本判断（`Build.VERSION.SDK_INT` 一行），而在状态机分支多**：

PC 工具侧设备状态：无设备（驱动 / USB 模式 / 数据线 / 未开调试）/ `unauthorized`（手机未点允许）/ `offline`（驱动或线材）/ 多设备。
App 侧 Shizuku 状态：未安装 / 已装未启动 / 已启动未授权 binder / 已授权。国产 ROM 另有额外步骤（如 MIUI 需「USB 调试（安全设置）」+ 账号登录）。

对策：检测层做成「状态机引擎」，每个状态映射一条定向引导文案与下一步操作；App 侧轮询无障碍 / 通知监听 / Shizuku 状态并在从系统设置返回时刷新；真机矩阵验证（至少覆盖 AOSP、MIUI、ColorOS 各一台）。

参考：开源项目 Open-AutoGLM-Android 已验证「Shizuku + AI 操控手机」技术路线（Android 8.0+，通过 Shizuku 实现 AI 手机操控）。

### 4.7 安全边界模型（定稿）

分级原则：**感知自动、操作确认、白名单管理、命令模板化**。

- 只读工具（读屏 / 通知 / 用量 / 应用列表）：自动执行；读到的外部内容标记「不可信」，进上下文时包裹声明，降低提示注入风险；
- 状态变更工具（停用 / 启用 / appops / 卸载 / 强制停止）：每次执行前弹窗确认（展示「将执行的操作 + 目标应用」），且仅允许操作白名单内的应用；
- 模拟点击 / 滑动：默认关闭，V2 提供，开启后仅限当前前台应用且每次确认；
- 命令模板化：工具参数只允许结构化字段（包名 / 开关值等），禁止自由 shell 拼接；
- 审计日志：记录工具名 / 参数 / 时间 / 结果 / 是否确认，本地存储可导出。

### 4.8 Agent 会话与数据模型

- 复用 Conversation 基础设施，新增会话类型 `AGENT`（与私聊 / 群聊同存储，气泡样式一致）；
- Agent 会话使用独立系统人设 + Agent 工具集，不走私聊的记忆策略工具（避免 read_memory 混入）；
- 会话内汉堡菜单：**人设卡复用私聊 PersonaPanel**（用户可不设置，不强制名字）；
- 未设置人设时默认提示词（冷峻语气，草稿待批）：「你是 Quiddity 的一个本地 Agent 助手。语气简洁克制，不寒暄、不编造；不确定的信息明确说明；所有操作以用户明确指令和已授权权限为准。」
- 独立 `AgentStore`（仿 `mini-apps.json` 方案）：白名单应用列表、权限等级设置、模拟操作开关（默认关）、审计日志（可导出）。

### 4.9 Agent 设置页结构（定稿）

入口：Agent 页左上角设置按钮。**页面核心 = 权限开启状态展示**；全局总设置仍生效。

**一、权限状态（核心）**
- 能力状态总览：无障碍 / 通知读取 / 使用记录 / Shizuku 四状态，未就绪显示「去开启」，按版本自动路由教程；
- 工具使用权限按三组展示、可单独开关：
  - **感知**：读屏 / 通知 / 用量 / 前台应用；
  - **读**：应用列表 / 系统信息 / 剪贴板；
  - **写（操作）**：停用 / 启用应用 / AppOps / 卸载 / 强制停止（需 Shizuku，未开通显示锁定）；
- 权限等级徽章：基础 / 进阶当前解锁状态；
- 白名单应用管理：添加 / 移除允许 Agent 操作的应用；
- 危险操作确认：V1 默认开启、不可关闭。

**二、数据与隐私（仅该模式）**
- 审计日志：查看 / 导出 / 清空；
- 清空 Agent 会话；
- 隐私说明：读屏 / 通知数据用途与本地存储声明。

**三、支持**
- 教程（App 侧，版本自动路由 + 品牌分类）；
- 我的QQ（复用现有客服入口）；
- 反馈投稿：提交截图 / 教程建议（为补图铺路）；
- 关于：Agent 模式版本与能力说明。

## 5. 决策记录（2026-08-10 定稿）

| # | 决策项 | 结论 | 理由 |
|---|---|---|---|
| 1 | 入口形态 | Tab 顺序 Agent(0) / 私聊(1) / 群聊(2)，默认私聊；私聊右滑 = Agent；Agent 会话列表与私聊 / 群聊同款组件；会话纯文本直排无气泡；设置入口左上角 | 定位核心模式；UI 走简洁直排流行风格 |
| 2 | 进阶通道 | Shizuku（定稿）；root 为可选增强，不列必需 | 免 root、可逆、门槛最低；Device Owner 弃用 |
| 3 | 安全边界 | 感知自动、操作确认、白名单、命令模板化、审计（见 4.7） | 防误操作与提示注入 |
| 4 | 自动化深度 | P0/P1 只做「读 + 系统命令」；模拟点击 / 滑动延后 V2 | 进阶需求（停用应用）全是系统命令；模拟操作误触风险最高 |
| 5 | 常驻形态 | 默认按需唤醒，不做常驻循环；通知监听仅用于读取 | 常驻耗电 + 国产 ROM 杀后台体验差；Android 14 FGS 有类型限制 |
| 6 | PC 工具 | Python + PyInstaller 单文件，仅 USB；命名「安卓端AGENT模式开启.exe」 | 包体小、开发快；无线调试在 11+ 手机本地完成，8-10 只有 USB |
| 7 | 设置页与菜单 | Agent 设置页核心 = 权限开启状态（感知 / 读 / 写三组 + 状态总览 + 数据隐私 + 支持）；会话内汉堡菜单保留人设卡（复用私聊） | 权限状态是用户最关心的；人设不强制设置 |

## 6. 风险与注意点

- **提示注入（最高）**：读屏内容不可信，网页 / App 内文字可能诱导模型执行危险命令。必须结构化工具参数、白名单、危险操作二次确认、审计日志。
- **隐私**：读屏 / 通知 / 用量数据敏感，需本地存储 + 明示告知。
- **用户门槛**：进阶权限开启依赖 adb / 第三方应用，非技术用户可能卡住，需引导方案（见对话讨论）。
- **兼容性**：国产 ROM 对无障碍 / 后台限制差异大，需真机矩阵验证。
