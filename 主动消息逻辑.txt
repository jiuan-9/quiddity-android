主动消息方案（方案二 · 定稿）

一、总则

系统不做任何发送决策干预。
时间库制定、发送与否，全部由 LLM 根据人设和上下文自主决定。
系统仅负责：定时触发、状态管理、返回值解析、消息发送。
本功能按会话独立，非全局功能。

二、功能开启流程

2.1 总设置开关
用户在「总设置」中开启该功能。
开启后弹出提示弹窗，内容如下：

若您决定开启此功能，建议将本应用的【电池优化】设为“不受限制”，并将【自启动】设为“允许”；
总设置仅表示您已了解该功能，您需前往对应会话中单独开启该会话的时间库功能。
【我知道了】

点击“我知道了”后关闭弹窗，总设置状态保存。

2.2 会话级开启
用户进入某个具体会话，在该会话的设置中开启“时间库主动消息”。
开启后，该会话立即触发第一次时间库生成。

三、时间库生成

3.1 生成时机
每天仅当天首次打开该会话时触发生成。
触发时，界面提示：“正在整理前一天的记忆！”
若当天已生成过，再次打开不再重复生成。

3.2 生成规则（由 LLM 执行）
输入依据：
  该会话的人设
  该会话的压缩聊天记录
输出格式：仅时间列表，24小时制，精确到分钟。
示例：
13:30
12:32
15:45
数量限制：
  最多不超过 5 个时间点
  可不满足 5 个，允许为空列表
时间点之间无强制间隔限制，由 LLM 根据人设自行把握。

3.3 时间库存储结构
[
  {"time": "13:30", "status": "pending"},
  {"time": "14:00", "status": "pending"},
  {"time": "18:00", "status": "pending"}
]

status 仅两种状态：pending / done

四、时间库更新与兜底

每次生成新库时，直接覆盖该会话的旧时间库。
若本次生成结果为空列表或生成失败：
  不采用本次结果
  继续沿用上一次的时间库
若该会话从未生成过时间库（无新库也无旧库）：
  该会话不注册任何定时任务
  系统保持静默，不消耗资源
  直到用户再次打开该会话触发生成

五、定时触发机制

5.1 触发方式
系统使用本地闹钟服务（如 Android AlarmManager）进行定时唤醒。
仅依赖手机本地时间，不依赖网络时间。
即使 App 被从后台清除，闹钟仍可唤醒应用进程（受系统省电策略影响，见弹窗提示）。

5.2 触发执行流程
当系统时间到达某个 pending 时间点时：

调用 LLM，输入：
   该会话的人设
   未压缩的聊天记录（若为空，则跳过本次决策，直接视为“不发送”）
   当前触发的时间点
LLM 根据人设和上下文，决定是否发送消息。
系统解析 LLM 返回值：
   若返回值严格等于独立数字 0（即仅返回 0，无任何其他字符）→ 系统拦截，不发送
   若返回值包含任何其他内容（包括文字、标点、0 带句号等）→ 视为“需要发送”
调用发送层，以普通聊天方式发送消息（独立头像，样式同微信）。
无论 LLM 返回 1 还是 0，该时间点的 status 均立即改为 done。

六、补偿与容错机制

6.1 触发延迟补偿（5分钟宽容窗口）
若系统因休眠或卡顿导致未在精确时间点触发（如 13:30 未触发，直到 13:32 才唤醒）：
  计算当前时间与未发送时间点的差值
  若 差值 ≤ 5 分钟 → 立即补发该时间点的消息
  若 差值 > 5 分钟 → 放弃该时间点，继续等待下一个 pending 时间点

6.2 网络/API 异常
若调用 LLM 时发生超时或网络错误：
  系统自动重试 1 次（延迟 5 秒）
  若重试仍失败 → 将该时间点标记为 done（不重试、不补发），进入下一个时间点

七、状态重置

每日首次启动 App 时：
  检查当前日期与上次重置日期
  若不同，将该会话所有时间库的 done 重置为 pending

八、任务注销

每次系统检查时间库后：
  若该会话数组中所有时间点均为 done → 立即注销该会话的所有定时闹钟，停止唤醒
  直到次日重置或新库生成后重新注册
若该会话无时间库（新库旧库均为空）→ 不注册任何闹钟，完全静默

九、已知局限性（无需代码处理，仅文档说明）

若用户在系统设置中强制停止（Force Stop）本应用，所有闹钟将被系统清除，定时功能失效。
用户需手动打开 App 后方可恢复。
该限制为安卓系统底层行为，应用层无法规避。

十、总结规则链

总设置开启 → 弹窗提示
会话级开启 → 当天首次打开生成时间库
存储为 [{time, status}]
到达 pending 时间 → 调用 LLM 决策
严格匹配 0 则拦截，否则发送
执行后标记 done
延迟 ≤5分钟补发，>5分钟跳过
全 done 则注销闹钟
每日 App 启动时重置所有 done → pending
